# Безопасность Админпанели

Этот документ фиксирует план безопасности для будущего админского клиента и admin API.

## Главное Правило

Обычные ключи игроков не должны давать права администратора.

Ключ игрока нужен только для добавления сборки и скачивания файлов. Для админского клиента нужна отдельная авторизация с более строгими ограничениями.

## Рекомендуемый Вариант

Сначала лучше использовать SSH, если сервером управляет один доверенный владелец.

- Админский клиент подключается по SSH.
- Сервер не открывает публичные admin HTTP endpoints.
- SSH-пользователя по возможности нужно ограничить папкой Flandosync и нужными service-командами.
- Админский клиент загружает файлы, пересоздает манифесты, ротирует ключи и перезапускает сервис через явные команды.

Admin API стоит добавлять только если SSH станет неудобен.

## Если Добавлять Admin API

Перед публикацией admin API должны быть готовы такие ограничения:

- Отдельный admin token или отдельный логин, не ключ игрока.
- Только HTTPS, если API доступен из интернета.
- Токены хранятся вне публичного репозитория.
- Короткоживущие сессии или подписанные запросы.
- Rate limit для входа и изменяющих действий.
- Audit log для загрузок, удалений, генерации манифеста, создания ключей и перезапуска сервиса.
- Ограничение размера загружаемых файлов.
- Строгая проверка путей, чтобы файл нельзя было записать вне папки сборки.
- Dry-run режим для опасных действий.
- Подтверждения для удаления файлов, ротации ключей и перезапуска сервисов.

## Web-Админка

Встроенная web-админка опциональна и выключена по умолчанию.

Рекомендуемые настройки:

- `admin_enabled`: `false`, если админка прямо сейчас не нужна.
- `admin_host`: `127.0.0.1` для доступа только с localhost.
- `admin_port`: отдельный порт, не порт публичного sync-сервера.
- `admin_token`: сильный отдельный admin-only token, либо переменная окружения `FLANDOSYNC_ADMIN_TOKEN`.

Рекомендуемый удаленный доступ:

```bash
ssh -L 8010:127.0.0.1:8010 user@your-server
```

Первая версия web-админки специально поддерживает только менее рискованные действия: список сборок, просмотр manifest и перегенерацию manifest с version/changelog. Загрузку файлов, удаление, управление ключами и перезапуск сервиса лучше добавлять только после бэкапов, audit log и дополнительных подтверждений.

## Более Безопасные Админские Действия

Админские действия должны быть узкими и явными:

- Загрузить моды в выбранную сборку.
- Удалить только файлы внутри выбранной сборки.
- Пересоздать один манифест.
- Ротировать один ключ.
- Перезапустить только настроенный сервис Flandosync.

Не стоит делать в админском клиенте универсальный удаленный терминал. Это удобно, но сильно повышает риск.

## Бэкапы

Перед опасными админскими действиями нужно создавать timestamp-бэкап:

- `server.py`
- серверных конфигов
- файлов ключей
- манифеста выбранной сборки
- файлов, которые будут удалены или перезаписаны

Бэкапы должны лежать вне публичной web-папки.

## Ограничение Доступа Игроков

Скачивание для игроков в будущем лучше перевести с постоянного общего ключа на временный download-token:

1. Клиент отправляет ключ игрока в `/project_by_key`.
2. Сервер возвращает данные манифеста и временный download-token.
3. Скачивание файлов требует этот временный token.
4. Token имеет срок жизни, rate limit и лимит параллельных скачиваний.

Это поможет защитить сервер, если у кого-то клиент зависнет в цикле загрузки.

## Не Коммитить

Нельзя выкладывать на GitHub:

- реальные ключи игроков
- admin tokens
- SSH-ключи
- публичные IP-адреса
- приватные домены
- пути живого сервера
- production-конфиги
