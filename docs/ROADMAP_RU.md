# Дорожная Карта Flandosync

Этот документ фиксирует идеи для следующих версий и рекомендуемый порядок реализации.

## v1.1.0 - Удобство Клиента

Цель: сделать клиент приятнее для обычных игроков без изменения серверного протокола.

- Контекстное меню сборки в списке.
- Переименование сборки локальным псевдонимом.
  - Пример отображения: `Моя сборка (aerocraft)`.
  - Серверное имя сборки не меняется.
- Удаление сборки из списка.
  - Перед удалением показывать диалог подтверждения.
  - Дополнительная галочка: `Также безвозвратно удалить файлы сборки`.
  - Галочка по умолчанию выключена.
- Экспорт логов из интерфейса.
- Улучшение отображения результатов синхронизации.
  - Отдельно показывать скачанные файлы.
  - Отдельно показывать пропущенные файлы.
  - Отдельно показывать удалённые лишние файлы.
- Базовый UX-проход.
  - Более понятные кнопки.
  - Более аккуратные сообщения об ошибках.
  - Защита от повторного запуска синхронизации.

## v1.2.0 - Настройки Клиента

Цель: убрать необходимость редактировать JSON вручную.

- Окно настроек.
- Настройка адреса сервера.
- Переключение темы.
- Сохранение настроек в `flandosync_settings.json`.
- Проверка доступности сервера из окна настроек.

## v1.3.0 - Стабильность И Производительность

Цель: сделать синхронизацию устойчивее на больших сборках.

- Кэширование `manifest.json` на клиенте.
  - Не скачивать манифест слишком часто без необходимости.
  - Показывать время последней проверки.
- Ограниченный многопоток скачивания.
  - Например 2-4 параллельные загрузки.
  - Ограничить нагрузку на сервер.
- Более устойчивые загрузки.
  - Таймауты.
  - Повторы.
  - Временные файлы.
  - Проверка хэша после скачивания.
- Более безопасное поведение при обрыве сети.

## v1.4.0 - Версионирование Сборок

Цель: дать игроку понятную информацию об обновлениях.

- Добавить версию сборки в манифест.
- Клиент хранит последнюю синхронизированную версию.
- При изменении версии клиент показывает предупреждение об обновлении.
- Показывать список изменений, если сервер предоставляет changelog.

## v1.5.0 - Ограничение Доступа

Цель: снизить риск перегрузки сервера без firewall-правил по IP.

Возможные подходы:

- Второй секретный ключ для скачивания файлов.
- Разделение ключей:
  - ключ добавления сборки;
  - краткоживущий download-token.
- Лимит одновременных загрузок на сервере.
- Лимит запросов на ключ.
- Блокировка слишком частых запросов.
- Отдача понятной ошибки вместо падения сервиса.

Рекомендуемый вариант:

1. `/project_by_key` принимает основной ключ.
2. Сервер выдаёт временный download-token.
3. Скачивание файлов требует этот token.
4. Token имеет срок жизни и лимит параллельных соединений.

Такой подход не зависит от IP и лучше работает для игроков с динамическими адресами.

## v2.0.0 - Admin Client

Цель: отдельный Windows-клиент для администратора сборки.

Возможности:

- Подключение к серверу по SSH или через отдельный admin API.
- Загрузка новых модов на сервер.
- Удаление модов с сервера.
- Перегенерация манифеста кнопкой.
- Просмотр текущих ключей.
- Создание новых ключей.
- Просмотр версии сборки.
- Публикация changelog.
- Перезапуск сервиса, если настроен systemd.

Важно: admin client должен иметь отдельную авторизацию. Нельзя использовать обычный пользовательский ключ как админский.

## Приоритет Реализации

Рекомендуемый порядок:

1. Контекстное меню, переименование, удаление сборки.
2. Окно настроек клиента.
3. Экспорт логов и красивый список изменений после синхронизации.
4. Кэш манифеста и стабильность загрузок.
5. Ограниченный многопоток.
6. Версионирование сборок.
7. Ограничение доступа и защита от перегрузки.
8. Отдельный admin client.
